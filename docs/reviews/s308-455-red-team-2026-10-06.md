## Findings (ranked by blast radius)

### 1. [ISSUE][MED][demonstrated] Extensionless repo script in a hook command is silently dropped when another token in the same command matches
extractScriptTokens matches only tokens ending in mjs|js|cjs|ts|mts|sh|ps1|py. A command that runs an extensionless repo executable alongside an enumerable script yields only the enumerable token, so the command is NOT flagged unenumerable; the extensionless script vanishes with no absent/outside/unenumerable entry and F1 stays green.
Demonstrated: command [node docs/x.mjs AND-AND sh docs/run] -> tokens=[docs/x.mjs] scripts=[docs/x.mjs] unenum=0; docs/run is invisible.
Current defense: none for this shape; the command is treated as fully enumerated. This is the attack goal (make the derivation silently drop one).
Exposure: ~0 percent of current runs, basis: counted in the live snapshot (real maat/shopify commands name only mjs/sh literals); latent for future command shapes. Verdict: BREAKS (latent). Proof-test: plugin-hooks: extensionless hook-run script is reported or forces unenumerable.

### 2. [ISSUE][MED][demonstrated] A partially-assembled script path (string concat / template in node -e) yields a bogus absent token and F1 passes with a NOTE, leaving the real executed script unprotected
node -e with a require of docs path assembled by concatenation splits to token x.mjs, classified in-repo; resolve(root,x.mjs) does not exist -> recorded as absent (a NOTE in both the generator and F1), never a failure. The actually-executed docs/x.mjs is neither protected nor reported.
Demonstrated: concat case -> tokens=[x.mjs] scripts=[] absent=1 unenum=0.
Current defense: the plan discloses that a runtime-built path is not enumerable, implying a hard fail. The behavior is a soft NOTE (F1 PASS), so the disclosed fail-closed property does not hold for partial assembly: a partial token masks it as absent rather than unenumerable.
Exposure: ~0 percent of current runs, basis: counted in the live snapshot (maat uses plain literals, captured correctly). Verdict: BREAKS (latent). Proof-test: f1: a command yielding only a nonexistent assembled token FAILS (not notes).

### 3. [SUSPICION][MED][derived] Snapshot-vs-live fidelity is checked only on a local human run; CI is unverified (treated as pass)
snapshotLiveDrift returns unverified when ~/.claude/plugins is absent (every CI run), and F1 files it as a NOTE, not a failure. The whole guarantee is therefore as fresh as the last local --write. A plugin upgrade that adds a new hook-executed script between local regenerations leaves that script unprotected with every CI gate green. Honestly disclosed in code (snapshotLiveDrift detail, F1 header) and plan section 3. Architectural (CI has no ~/.claude). Verdict: UNPROVEN; settled only by a human running node src/qa/protected-path-list.ts locally after any plugin change; who runs it: the human at K activation.

### 4. [SUSPICION][LOW][code-traced] exec/execSync/non-node-spawn children of a hook script are silently unfollowed (asymmetric fail-closed)
spawnedScripts throws on a computed node-spawn with a non-literal script arg (good), but exec/execSync/non-node spawn are not in SPAWN_FNS, so a child launched via execSync of a node command string is skipped with no throw and no report. Disclosed in the code comment. The three real scripts use execFileSync(process.execPath, ...) (followed) and execFileSync(git, ...) (not a repo script), so no current miss; the scripts are themselves protected (session-immutable). Verdict: UNPROVEN, mooted for the current closure; re-check on any plugin-script rewrite.

### 5. [SUSPICION][LOW][code-traced] maat.json and .gitmodules (read by adr-cache to drive the autoSync git fetch/merge) are unprotected
docs/adr-cache.mjs reads maat.json (adr.dir, autoSync, upstreamBranch) and .gitmodules to decide an autoSync git fetch + git merge --ff-only into the ADR submodule. autoSync defaults OFF and the path only merges files (no code execution). Out of #455 declared scope (executed scripts, not the config those scripts read). Blast radius tiny (ADR-catalog data tamper only, regenerated from disk). Verdict: UNPROVEN, out-of-scope note.

## Scariest unproven assumption

Finding 3: the snapshot fidelity to the live plugins is only ever proven on a local human --write/F1 run; in CI it is unverified and passes. Between local regenerations, a plugin upgrade that adds a hook-executed repo script is unprotected with all gates green. Disclosed and architectural, not a code defect.
