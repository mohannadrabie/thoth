## Attacks, ranked by exposure x irreversibility x silence

### 1. [ISSUE][HIGH][demonstrated] #477 NOT FIXED: the new census still misses real `.claude` names on pinned 2.1.289

**Assumption broken.** The census's own contract (`Extracted.census` doc comment) is "every `.claude` name found ANYWHERE in the binary, by any shape". The four shapes it implements are:
- the `".claude","<name>"` pair;
- a whole literal whose only allowed prefixes are `~/` and `./`;
- a call to a window getter;
- a variable bound to a window getter, within 600 chars.

**Probe** (scratchpad `r2/verify.ts`, the shipped `extractWriteDeny` on real bytes):

```
2.1.289 census size 75 | missing: checkpoints,mailbox,agent-registry.json,first-run,assistant-daemon-state.json,.credentials.json,history,todos,statsig,remote | present: file-history,agent-memory,agent-memory-local,ide
2.1.267 census size 72 | missing: (same 10) | present: file-history,agent-memory,agent-memory-local,ide
```

Where the misses come from (scratchpad `r2/ctx2.ts`, `r2/alias.ts`, 2.1.289 JS source):

1. **Glob-prefixed literals.** This is Claude Code's own runtime file list, which it appends to `.git/info/exclude` under the marker `pe="# claude-code-runtime"`: `var Le=["**/.claude/scheduled_tasks.lock","**/.claude/scheduled_tasks.json","**/.claude/routines/.state/","**/.claude/worktrees/","**/.claude/checkpoints/","**/.claude/mailbox/","**/.claude/agent-registry.json","**/.claude/agent-memory-local","**/.claude/first-run","**/.claude/assistant-daemon-state.json"]`. This is the vendor's own enumeration of what it writes under a project's `.claude/`. The census misses 5 of its 10 entries (50%), because the literal prefix `**/` is not in the allowed set. `mailbox` and `agent-registry.json` are multi-agent coordination files, the same prompt-reaching class as `agent-memory`.
2. **A config-dir getter that is not the window's.** `Lf(DS(),".credentials.json")`, where `DS` is a config-dir getter other than the window's `we`. That is `~/.claude/.credentials.json`, the OAuth credential store. The binary's own classifier marks a profile-store write as "substitutes the credential and organization behind managed settings", `classifierApprovable:!1`. It is not in the census, not judged, and not on the protected list (`grep -n credentials src/qa/protected-path-list.ts` returns nothing). The disclosed limit names "an alias of an alias" through a variable, not a second getter function.
3. **Rule strings.** The built-in rule list has `"Read(~/.claude/history*)"`, `"Read(~/.claude/todos/**)"`, `"Read(~/.claude/statsig/**)"` and `"Read(~/.claude/.credentials.json)"`. These are whole literals whose prefix is `Read(~/`, so the census misses them.
4. **Disclosed-limit cost, measured** (scratchpad `r2/bind.ts`): two more names are reachable only beyond `BIND_WINDOW` (`daemon.log.1`, `speculation`). The limit is disclosed and is not counted here.

What survives (shapes I attacked that hold):
- **path.join with more segments:** `(oe(),".claude","agent-memory",r)` is caught.
- **Template literals:** 220 mention `.claude`, and none carries a literal name after `.claude/`; each is `${var}/.claude` or `.claude/${var}`.
- **Bytecode constant pools:** 1 standalone `.claude` constant, whose follower is covered.

**Exposure:** ~100% of a2 census runs against pinned 2.1.289. At least 9 real names are missed, 5 of them out of Claude Code's own 10-entry runtime-write list. Basis: measured. Silent, because a2 judges exactly what the census prints.

**Why this is structural, not a fifth shape.** Round 1 found a call base; round 2 finds a glob prefix, a second getter and a rule-string prefix. The census is still a whitelist of shapes in a design that says it fails closed. Two cheap changes catch every name above (my probes used both) and only add noise, which this design already accepts:
- (a) Take every quoted string containing `.claude/<name>` with any prefix, dropping a trailing `.` so prose such as "hooks." is trimmed.
- (b) Take the getter set from every function or `cs(()=>…)` binding whose body mentions `CLAUDE_CONFIG_DIR` or ends `".claude")`, not only the window's ids.

**Required failing test:** **`CC-census/glob-prefix-rule-string-and-second-getter`**. A fake binary has `var Le=["**/.claude/mailbox/"]`, `"Read(~/.claude/statsig/**)"`, and `function DS(){return process.env.CLAUDE_CONFIG_DIR??"x"}...Lf(DS(),".credentials.json")` outside the window. Assert `mailbox`, `statsig` and `.credentials.json` are census names. Then re-run `r2/verify.ts` against 2.1.289 and expect an empty missing list, apart from the server-side path `/home/claude/.claude/remote`.

### 2. [ISSUE][LOW][demonstrated] The git check reads the work tree, so assume-unchanged or skip-worktree lets uncommitted bytes through

`gitTrackedAndClean` asks `git ls-files --error-unmatch` and `git diff --quiet HEAD`, then `applyFiles` reads the work-tree file. Probe (scratchpad `r2/gitcheck.ts`, temp repo, the real `gitTrackedAndClean` and `applyFiles`):

```
A staged-new: ...deltas\a.json is modified relative to HEAD (a delta must be the committed file)
B modified: ...deltas\a.json is modified relative to HEAD (a delta must be the committed file)
B modified+assume-unchanged: ACCEPTED | bytes on disk: {"toolExec":{"version":"2099-12-31"}}
B modified+skip-worktree: ACCEPTED
B applyFiles: {"changed":true,"missing":[]} | tool version now: 2099-12-31
C symlink not creatable here: Error: EPERM: operation not permitted, symlink ...
D dotdot REFUSED: Error: delta ...\outside.json is outside docs/qa/judgment-deltas/
E junction REFUSED: Error: ...\jdeltas\outside.json is not tracked in git
```

Staged-but-uncommitted, `..` and a junction'd delta dir are all refused (good). `git update-index --assume-unchanged` (or `--skip-worktree`) on a committed delta makes the check pass while the applier applies edited bytes. On POSIX, a committed symlink delta has the same effect, because `readFileSync` follows the link to untracked content. That part is code-traced only, since symlink creation needs a privilege this machine lacks.

Precondition: write access to the delta (a protected path) plus a deliberate `update-index`. Anyone who has that can also write the protected judgment JSON directly, so this does not escalate past what that already gives. Exposure: assumption, so LOW.

Fix, which removes the whole class: apply the committed blob (`git show HEAD:` plus the delta path) instead of the work-tree bytes. Test: **`JA-applier/applies-committed-blob-not-worktree`** (modify a committed delta, set assume-unchanged, and expect either the committed content or a refusal).
