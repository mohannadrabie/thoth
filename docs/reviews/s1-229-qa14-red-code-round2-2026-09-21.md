## 4. Item 2: correctness of the delta

**`makeExistsAtBase` (`src/qa/reference-resolver.ts:746` to `src/qa/reference-resolver.ts:758`, wired at `src/qa/reference-resolver.ts:845`).**
- Merge-base semantics are right for the three-dot range. The diff is `<base>...<head>` (`src/lib/git.ts`, `diffText`, untouched), whose old side is the merge base. The helper asks `git merge-base <base> <head>` once (`??=` on a memoized promise, `src/qa/reference-resolver.ts:753`) then `git cat-file -e <merge base>:<path>`.
- Demonstrated against real git in a scratch repository: a path present at the branch point reads true; a path the base branch gained after the branch point reads false (a tip-of-base check would have said true); a path that never existed reads false; an unknown base ref reads false; a nonexistent working directory reads false (the runner returns a non-zero code rather than rejecting). The rejection route is covered through `existedAtBase` (`src/qa/reference-scope.ts:286`, try/catch to absent) and its unit test.
- Arguments are passed as an array, no shell. The path follows the first colon, so a space or a further colon in a path is literal. A base value beginning with a dash would be read as an option, exactly as it already is in the pre-existing `<base>...<head>` token given to `git diff`; this diff makes nothing worse.
- Error path: any failure reads as "absent", which routes the file to a whole-file scan (stricter, never a pass). A diff read failure short-circuits earlier (`src/qa/reference-scope.ts:314`), so no `git cat-file` runs at all.
- Full-tree runs never call it (`src/qa/reference-scope.ts:314`); the full-tree mutant in section 6 proves the guard is load-bearing.
- No edit to `src/lib/git.ts`: empty diff against master.

**Move rule (`src/qa/reference-scope.ts:240`).** One condition: the removal's path is scanned by this run and is an append-only record. Re-reading the function, the multiset, the carriage-return stripping and the "spent across every file" behavior are unchanged. The old explicit mirror clause is redundant (the mirror is not an append-only record) and its deletion is safe: the mirror laundering test still turns red under the mutant that lets the mirror license (section 6, M7b).

**Canonical-format mirror cut (`src/qa/reference-scope.ts:213` to `src/qa/reference-scope.ts:226`).** Confirmed: the real `docs/.maat-state.json` is canonical, equal to the two-space `JSON.stringify` of its parse (one trailing newline aside) at HEAD, at master and in the working tree, and the working-tree copy holds no carriage return. The only writer I found (`docs/adr-cache.mjs`) writes exactly `JSON.stringify(state, null, 2)` plus a newline. The cut fails closed in the right direction: a duplicate key, an escaped key spelling, a comment, a byte order mark, a trailing comma, tab indentation, compact form or two trailing newlines each return the text whole. A non-object value under the mirror key is kept (authored). The cost the doc comment states is real: a writer format change makes QA-14 red on the mirror text, loudly.

**stderr NOTE (`src/qa/reference-resolver.ts:839`).** The `diffText` dep prints one line naming the first line of the error and saying the records are scanned whole, then rethrows so the module's whole-file fallback runs unchanged. It fires only when a diff is actually requested (an append-only record is present and the run is not full-tree). The test forces `git diff` to fail with `GIT_EXTERNAL_DIFF` while the file-list call still works, and asserts exit 1, the old example reported on the whole file, and the NOTE on stderr; removing the print turns that one test red (section 6, S1).
