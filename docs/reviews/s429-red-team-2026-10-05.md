## Attack 1 — [HIGH] The Bash tool sources the active shell-snapshot on EVERY call; that directory is not protected

Evidence: demonstrated + code-traced. Exposure: live 0% (gate unwired); latent ~100% of Bash tool invocations once K ships, in any session where ~/.claude/shell-snapshots/ is writable. basis: counted-in-code (protected-list probe) + measured (spawn cmdline). Security / self-protection -> exempt from the rule-21 3% cap.

Scenario: /proc/$$/cmdline for the Bash tool shows the wrapper is literally
  bash -c "source /c/Users/<user>/.claude/shell-snapshots/snapshot-bash-TS.sh 2 dev null || true && ... && eval GATED-COMMAND".
The gate (once K wires it) evaluates the command string it is handed (the eval-d part), not the sourced snapshot prepended to every invocation. A session that writes the active snapshot file plants shell code that runs, unexamined by the gate, on every subsequent Bash call in the session. This is precisely the vector #446 just protected for login profiles (a session that can write one can prepend a planted PATH directory for its next shell) only stronger: the snapshot is sourced on EVERY Bash call, not just a future login shell, and it sits one layer below the gated string.

Current defense (honestly assessed): none. protectedPaths().all covers ~/.claude/ settings.json, commands, skills, agents, plugins and ~/.claude.json, but NOT ~/.claude/shell-snapshots/. Probe output: UNPROTECTED ~/.claude/shell-snapshots/snapshot-bash-x.sh. No Edit-deny entry, no kernel named-path entry, and it is not listed as a disclosed residual anywhere in the plan, judgment file, or #446 residual R1 (R1 discloses only BASH_ENV/ENV and other shells). The threat model already treats ~/ as session-writable (that is why ~/.bashrc is protected) so this is an omission, not an out-of-model case.

Verdict: BREAKS (gates K, not today unwired system).
NAMED proof-test before K merges: F1-shell-snapshot-dir-protected: assert protectedPaths(root).all contains a ~/.claude/shell-snapshots/ directory entry and the generated deny rules refuse a write under it (decide() probe, as F1). Fix: add ~/.claude/shell-snapshots/ to namedPaths() and regenerate with --write. One-line fix.

## Attack 2 — [MED] authorable-content-protected is false for nested / monorepo / worktree .claude/skills|commands|agents

Evidence: code-traced + doc-backed. Exposure: live 0%; latent = any repo with a subdirectory .claude/ (monorepo packages, and .claude/worktrees/W/). basis: counted-in-code + vendor docs. MED (a planted skill dynamic-context command injection is itself permission-checked per Claude Code docs, and the gate is unwired).

Scenario: the Skill/SlashCommand residual rests on the session cannot author the content. The protected entries are root-anchored (.claude/skills/, canonicalized project-relative; Edit-deny Edit of /.claude/skills/ ** anchored at repo root). Claude Code loads skills from .claude/skills/ in every parent up to repo root AND from nested subdir/.claude/skills/ (loaded the first time Claude reads/edits a file in that subdir). Probe output: UNPROTECTED packages/a/.claude/skills/s/skill.md, UNPROTECTED .claude/worktrees/w/.claude/skills/s/skill.md, UNPROTECTED .claude/worktrees/w/.claude/commands/c.md. A session can author packages/x/.claude/skills/evil/SKILL.md (or under .claude/worktrees/), then trigger its load by working in that subdir.

.claude/worktrees/ is deliberately NOT protected per the plan, but the plan disclosed limit names only --plugin-dir / settings pointing outside the roots. It does NOT disclose that in-repo nested and worktree .claude/ dirs defeat the authorable-content condition. The completeness claim (the session must not author it) is therefore broader than true.

Current defense (honestly assessed): partial and undisclosed. Mitigating layer: per vendor docs, a skill dynamic-context command injection is checked against permission rules first (deny/ask aborts), so a planted skill does not get a free un-gated shell (why this is MED, not HIGH). But the residual condition as written and as disclosed is still incomplete.

Verdict: BREAKS (condition not met for non-root dirs), severity MED.
NAMED proof-test: F1-nested-skill-dirs-covered-or-disclosed: either extend the generated rules to deny writes under any **/.claude/ skills, commands, agents (prefix rules, not root-anchored), or add an explicit residual line to the judgment reason + plan stating nested/worktree .claude/ content is unprotected and relies on the injected-command permission check. Pick one; test it.
