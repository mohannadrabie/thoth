## 5. Design

**Where:** a new module (reference-scope.ts, in src/qa) holding pure functions, plus a new test file beside it. The resolver keeps its classification logic byte-identical; `main()` replaces its file-reading loop with one call into the new module, and the two file-naming edits (P5) touch the resolver's `Citation` type, the pass-2 loop in `resolveIssueCitations`, and one line in `summarizeCitations`.

| # | Mechanism | Rule | Fails closed when |
|---|---|---|---|
| P1 | Added-text-only scan for append-only records: docs/decisions.md, docs/decisions-archive.md, docs/REVIEW_LOG.md, CHANGELOG.md, and every file under docs/reviews/ | Text scanned = the lines the diff adds to that file (parsed from the existing `diffText`, unified diff), minus any added line that is byte-identical (trailing CR ignored) to a line the same diff removes anywhere. An identical add-and-remove pair is a move (the archive sweep, a reorder), not new text | The file is absent from the parsed diff (C-quoted path, pure rename, mode change): whole file. `diffText` throws: whole file. Full-tree fallback (zero SHA) or no diff: whole file |
| P2 | Generated-mirror exclusion: in docs/.maat-state.json, every `adrCatalog` key (top level and inside nested `priorScope` snapshots) is dropped before scanning; the rest of the file is scanned whole | The mirror is a cache regenerated from ADR files under adr/, which this repository does not author and QA-14 never scans (submodule). All other fields, including authored notes and tier text, stay under the gate | The file does not parse as JSON: whole file |
| P3 | Everything else unchanged: living files (STATE.md, backlog.md, CLAUDE.md, REQUIREMENTS.md, plans, source, hooks) are read whole from disk as today; `*.test.ts` stays exempt | | |
| P4 | Clear the standing failures that live in files the Manager ruled editable in place: docs/STATE.md (5, in two sentences of prior resume-point prose) and docs/backlog.md (4, in four bullets). Reword each sentence so it describes the example instead of quoting it; keep every number in those sentences unchanged (QA-15 reads them) | STATE.md and backlog.md are scanned whole, so the failures can only be removed, not scoped | |
| P5 | Name the file in each failure line: `Citation` gains optional `file`; `resolveIssueCitations` pass 2 tags each citation with its file; `summarizeCitations` appends ` [file: <path>]` when `file` is set | `scanReferences` output is unchanged (no file), so existing tests are untouched | |

**Why P1 is not an exemption:** nothing is keyed on a token. A bad citation on any line a diff adds, in any file, is scanned. The one case that passes is a line that is byte-identical to a line the diff removes, which is text that already existed. A line that is edited even slightly is new text and is scanned whole; that is the safe direction (an edited historical row that quotes an example is re-flagged).

**Why P2 is separate from P1:** the file is regenerated wholesale (the baseline diff shows 1497 insertions and 763 deletions in one story), so an added-text rule would re-scan the whole mirror every time.

**Prototype of P1 and P2 (spike, not shipped):** over the baseline range it reduces 26 failures to 6 (STATE.md 5, patterns.ts 1). Over the 15-merge history it reduces failures in every merge and leaves 0 failures in 4.

**Not done, by design:**

- No baseline or allowlist file, no per-token list, no in-file marker (the Issue #193 and Issue #136 class).
- No change to ci.yml, to `git.ts`, or to `classify*`/`scanReferences`.
- Full-tree mode stays whole-file everywhere.
- New docs/reviews/ files are scanned in full (every line of a new file is added).

## 15. Residuals to disclose in the close-out

- Full-tree mode stays red by design: whole-file everywhere, 110 failures in immutable reports, 83 in 19 other files (measured at 22b7141). Final numbers measured in Phase 2.
- A new review report that quotes example references is new text and fails. Mitigation is that the standing names no longer appear in diff-mode output.
- An edited historical row (ratification flip, strike-through) is re-scanned whole; if it holds example references it fails until reworded, or the edit is made by a move.
- A PR editing REQUIREMENTS.md, CLAUDE.md, manager-summary-format.md, adr-cache-check.md, an older plan, a hook or patterns.ts turns red on that file's standing failures (D4).
- A non-default `diff.mnemonicPrefix` or `diff.noprefix` git configuration makes the diff parser miss every path; the result is whole-file scanning (stricter), never a pass.
