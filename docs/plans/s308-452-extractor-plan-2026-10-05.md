# Plan: #452 write-deny extractor, both directions plus installed-version check (S7, k-blocker, severity:med, label pol)

Phase 1 plan, Ptah, 2026-10-05. ADR cache: HIT, 38 ADRs (fp 63531e7). No ADR names this surface; the rules that bind are CLAUDE.md's completeness rule and the sensitive-area list (evidence/audit trail).

## Story
The write-deny extraction test must fail when the extraction and the judgment file disagree in EITHER direction, and when the installed Claude Code is not the version the judgments were made for. Measured today with 2.1.267: extracted user 31, project 12, mcpJson true; judged user 31, project 12, projectRoot 1; the sets are equal, so exact equality can be enforced now with no judgment-file edit.

## Design
Pure logic lives in src/qa/claude-code-write-deny-extract.ts (new exports); the CLI wrapper is new; the test file gets new cases.
- `coverage(ex, j)` returns `{ unjudged: string[], judgedNotExtracted: string[] }` over user, project, and projectRoot `.mcp.json`. `unjudged()` stays (existing test unchanged).
- `parseClaudeVersion(text)`: `/^(\d+\.\d+\.\d+)/` on the first line, else undefined.
- `installedClaudeVersion(binary)`: `execFileSync(binary, ["--version"], {timeout: 10000})`, no shell. It queries the SAME binary the extractor read (locateClaudeBinary), not whatever `claude` is on PATH.
- `checkExtraction(env, versionProvider?)` returns a tri-state `{status: "PASS" | "FAIL" | "SKIPPED", reasons: string[]}`:
  - binary absent: SKIPPED("no installed Claude Code binary") unless `THOTH_REQUIRE_CLAUDE=1`, then FAIL (fail closed).
  - binary present but `--version` throws, times out, or is unparseable: FAIL.
  - parsed version != `judged.claudeCodeVersion`: FAIL ("re-run extraction, re-judge every new entry, then bump claudeCodeVersion").
  - extraction throws (anchor not found): FAIL.
  - any unjudged or judgedNotExtracted entry: FAIL, each listed.
  - else PASS.
- The existing "known entries present" sanity check is superseded by equality; keep it only as a message aid.

## CI behavior (no red on a runner without claude)
Default `npm test` on ubuntu CI: the installed-binary test calls `t.skip("SKIPPED: no installed Claude Code binary ...")` (node:test counts it as skipped, never passed). The both-directions logic is covered by pure tests that need no binary, so CI still proves the instrument works, including the 4-of-31 mutant. The live check is enforced where K activates: K readiness runs the CLI with `THOTH_REQUIRE_CLAUDE=1`, where absence is FAIL, not skip. Dev machines with claude installed run it live; a CLI auto-update makes the test red until re-judged, which is the intent.

## Name readiness should call
