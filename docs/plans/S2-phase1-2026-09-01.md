## 2. Acceptance criteria (7/7, all traced to REQUIREMENTS.md §3/§3.1 + ADR-0021, none derived)

1. **POL-01** — verdict changes when only fixture rule data changes; no operator-tunable value hardcoded in kernel code.
2. **POL-02** — rule data model carries optional multi-line `rationale`; round-trips unchanged through the schema validator.
3. **POL-04 (record shape only)** — every `ActionRecord` instance carries at least the 7 §3.1 fields (schema/type check); kernel branches on none outside them (structural/type check). No normalizer/registry work.
4. **POL-05** — `source: opaque` → deny; non-empty `unresolved` → deny; `parsed`/`structured` + empty `unresolved` → not denied by this rule; `deferred: true` on an otherwise-denying record still denies (SUR-09).
5. **POL-06** — unknown key rejected with `{message, field, expected}` naming it; missing required field, same shape; valid fixture passes.
6. **POL-08** — pure merge over defaults < central < project; defaults-only unchanged; three-way conflict resolves deterministically to project's value.
7. **POL-11** — structural/lint check proves no fs/network/process/timer/vendor-SDK import in the kernel's module boundary; kernel callable with only explicit arguments.
