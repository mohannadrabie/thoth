## Acceptance criteria, each mapped to a named test or check

Every check takes a settings-file path argument and defaults to .claude/settings.json. All tests are `node --test` files, written failing first, named `src/qa/<file>.test.ts` unless stated.

### Merge script, src/qa/k-settings-merge.ts (pure function plus CLI)

- A1. Existing keys are untouched: `k-merge: existing keys preserved byte-semantically`.
- A2. hooks.PreToolUse gets exactly the proposal entry (matcher, command and timeout 60 from the proposal JSON): `k-merge: appends the proposal entry`.
- A3. Merging twice equals merging once: `k-merge: second merge is a no-op`.
- A4. permissions.deny = existing Bash entries plus generated Edit entries, sorted and de-duplicated. The Edit set comes from `protectedPaths` and `editDenyEntries` plus `NESTED_EDIT_GLOBS`, never typed: `k-merge: deny = existing Bash + generated Edit, sorted, deduped`.
- A5. The CLI dry run is the default and writes nothing; `--write` writes: `k-merge CLI: dry-run default writes nothing`.
- A6. (D6) The dry-run output equals a checked-in proposed-settings fixture produced by the CLI: `k-merge: dry-run output equals checked-in proposed-settings fixture`.
- A7. Bad input exits nonzero (settings not JSON, proposal missing its matcher): `k-merge: fails closed on bad input`.

### K3, `K3-edit-deny-covers-fixture` (src/qa/k3-edit-deny-covers-fixture.ts)

- B1. Every generated protected path has its Edit entry in the target file (existing `missingEditDenies`): `K3: passes on merge dry-run output`.
- B2. `K3 mutant: drop fixture line` fails.
- B3. `K3 mutant: drop ~/ line` fails.
- B4. A target with no permissions.deny, or unparseable JSON, fails (no vacuous pass): `K3: empty or malformed target fails`.
- B5. The CLI takes a path argument, defaults to .claude/settings.json, and exits 1 on any miss.
- B6. `npm test` runs it on the dry-run output and every mutant. The real-file run lives only in `qa:k-readiness`. The assertion that the real default path is red until wired lives in the readiness test, not the default suite.

### K5, `K-pretooluse-entry-uses-launcher` (src/qa/k5-pretooluse-entry-uses-launcher.ts)

- C1. The entry command equals the proposal's `proposedCommand` byte for byte, and the matcher equals the derived matcher: `K5: passes on dry-run output`.
- C2. 8 mutants, one test each, all must fail (`K5 mutant: <name>`): bare `node <gate>`; trailing `|| true`; trailing `; exit 0`; `echo <launcher> <gate>`; `bash` for `sh`; PowerShell missing from the matcher; Monitor missing; RemoteTrigger missing.
- C3. The mutant count is asserted from the exported mutant array, not typed: `K5: mutant list length asserted by instrument`. A missing or duplicate PreToolUse entry fails: `K5: absent or duplicate entry fails`.
- C4. The matcher is compared to the proposal JSON's `proposedMatcher` and checked by the matcher-drift extractor over the same file. This closes #401 at K.

### #442, worktree emission (src/qa/protected-path-list.ts)

- D1. `--form=relative` emits one ready-to-paste `Edit(...)` line per target: `worktree-targets: relative form`.
- D2. `--form=absolute` emits the `//`-prefixed absolute form: `worktree-targets: absolute form`.
- D3. Both forms are tested on a synthetic linked worktree (tmp dir with a gitdir pointer, a commondir file and config.worktree), directory-entry forms included: `worktree-targets: both forms over synthetic linked worktree`.
- D4. A missing or unknown `--form` exits nonzero with nothing on stdout: `worktree-targets: missing or bad --form exits nonzero`.
- D5. A main checkout emits nothing, exits 0, and says so on stderr: `worktree-targets: main checkout empty`.
- D6. Commits use `refs #442`, never Fixes.

### `qa:k-readiness` (src/qa/k-readiness.ts plus npm script)

- E1. Read-only: a spied command runner allows only read commands (gh issue list, gh label list, git merge-base, git rev-parse, node src/qa/...): `k-readiness: read-only`.
- E2. Exits 1 unless every precondition in plan section 2 holds. Each row prints PASS, FAIL or MISSING: `k-readiness: exit 1 if any row not PASS`.
- E3. Every row is a running query, none hand-typed:
  - open k-blocker Issues
  - each fix branch an ancestor of origin/master
  - the git-rg-lever-preflight result
  - protected-path-list drift
  - gate-command-path, gate-launcher-pin, gate-matcher-drift, gate-manifest and gate-latency-budget on the real file
  - K3 and K5 on the real file
  - the K1 decisions row (Human = Y)
  - the K4 decisions row
  - `CC-extraction-covers-judged` (#452)
  - `F1-settings-named-scripts-judged`
  - the latency allow-path row
  - Test: `k-readiness: unbuilt rows report MISSING and fail`.
- E4. Blockers come from `gh issue list --label k-blocker --state open --json number,title`. It fails closed if gh is absent, errors or returns non-JSON, and if the label does not exist (`gh label list`): `k-readiness: lists blockers from gh`, `k-readiness: gh missing fails closed`, `k-readiness: label missing fails closed`.
- E5. Empty list: a second, independent query (`gh issue list --state open --json number,labels`, filtered locally) must agree with the first. If they disagree, the row FAILs with "list lag or label drift". If both are empty, the row passes and prints `0 open k-blocker issues (label exists, N open issues total)` with N live. The joint-lag residual is disclosed in the runbook.
- E6. K1 and K4 are parsed from the docs/decisions.md table; with no K1 row with Human = Y, the row FAILs: `k-readiness: K1 absent fails`, `k-readiness: K4 row found`.
- E7. At stage 0 the real run exits 1. This is a manual or integration step, not in default `npm test`: `k-readiness: stage0 real run is red by design`.
- E8. The readiness test with injected fake runners is in `npm test`; the real-repo run is not.
