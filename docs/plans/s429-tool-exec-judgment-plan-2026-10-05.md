## 3. Design

New committed data file docs/qa/tool-exec-judgment.json (single source, beside `tool-inventory.json`; the inventory is generated by `vendor-tool-inventory.ts` and a re-vendor would overwrite hand judgments, so they must not live in it):
`{ version, judgments: [ { tool, judgment: "exec-routed" | "exec-residual" | "not-exec", reason: "<one line>", residualCondition?: "inner-calls-gated" | "none" | "authorable-content-protected" } ] }`.

Derived, never retyped:
1. K matcher = the `exec-routed` tools joined with `|`, sorted, then `mcp__.*`. Result: `Bash|Monitor|PowerShell|RemoteTrigger|mcp__.*` (alternation order is irrelevant to the regex). A test asserts the proposal JSON and md carry exactly the derived string.
2. `pendingHumanDecision` = the `exec-residual` tools, each entry gaining `residualCondition` (and keeping `routingBreaks`). Monitor and RemoteTrigger leave the list (now routed). Test-pinned equal to the judgments' residual set; the md table is edited once to match and a test checks every residual tool appears there.
3. AP-12: `ADDED_BUILTINS` gains `SendMessage` (and the literal mutant list in that file), and a test pins AP12_NAMED union ADDED_BUILTINS (read by AST) equal to exec-routed union exec-residual, so the two cannot diverge in either direction. Making AP-12 read the judgment file instead is a larger change to a sensitive instrument and is not recommended.
4. SendMessage stays classified `remote-mutating` (never read-only); AP-12 already accepts that.

Skill and SlashCommand (ruling 3): add to `namedPaths()` the directory entries `.claude/commands/`, `.claude/skills/`, `.claude/agents/`, `~/.claude/commands/`, `~/.claude/skills/`, `~/.claude/agents/`, and `~/.claude/plugins/` (plugin skills and commands load from it). Regenerate with `--write` (never hand-edit the generated files). Honest limit, stated in the judgment reason: this stops the SESSION writing those files through the gate (Bash and mcp, once K routes them) and through the Edit-deny list (Edit and Write tools, once K ships the settings text). It does not make installed plugin or marketplace content trusted, and it cannot cover a skill directory named through `--plugin-dir` or a setting pointing outside those roots (not enumerable, unmeasured). `.claude/worktrees/` is deliberately NOT protected. If the Manager does not accept that residual, Skill and SlashCommand flip to exec-routed (matcher `Bash|Monitor|PowerShell|RemoteTrigger|Skill|SlashCommand|mcp__.*`; both then unusable): a one-word change in the judgment file, and every derived artifact follows.

## 5. Acceptance criteria, each mapped to a named failing-first test

Written failing first (the data file and helper do not exist). New src/qa/tool-exec-judgment.test.ts plus a small pure helper src/qa/tool-exec-judgment.ts (load, validate, derive matcher and residual list) so mutants run on in-memory copies. The existing K test file is extended, not rewritten.

1. Every name in the vendored inventory `tools` has exactly one judgment with a non-empty reason, and no judgment names a tool absent from the inventory. Test `K-every-vendored-tool-judged-exec` (red-team's required name).
2. Mutants on the checker: an inventory copy with a new name and no judgment fails and names it; an empty reason, a duplicate entry and a dead (unvendored) entry each fail. Tests `K-every-vendored-tool-judged-exec mutant: unjudged new tool`, `... empty reason`, `... duplicate`, `... dead entry`.
3. The proposed matcher equals the matcher derived from the judgments; every exec-routed tool is matched, no exec-residual or not-exec tool is. Test `K-matcher-derived-from-judgments`. Mutants: dropping Monitor, RemoteTrigger or PowerShell fails; an exec-residual tool added to the matcher fails.
4. `pendingHumanDecision` tools equal the exec-residual set, each with a known `residualCondition` and non-empty `routingBreaks`, and no routed tool remains. Test `K-pending-equals-residual-judgments`. The existing `K-matcher-covers-arbitrary-exec` tests keep passing.
5. SendMessage is in the AP-12 arbitrary-exec set, is never read-only, and is seeded as a mutant like the other ADDED_BUILTINS. Test `AP12-sendmessage-is-arbitrary-exec` (red-team's required name). And `AP12-set-equals-exec-judgments` (AP-12 arrays by AST equal exec-routed union exec-residual) with a mutant removing one name.
6. The K markdown and JSON agree on the matcher; the md names every residual tool and no routed tool in the pending table. Test `K-md-matches-judgments` (extends the existing third K test).
7. Authorable exec content is write-protected: `protectedPaths(REPO_ROOT).named` contains the seven directory entries and the shipped rules deny a write under each (decide() probe as in F1). Test `F1-skill-command-content-protected`. `npm run qa:protected-path-list` exits 0 after `--write`. Negative probe: a write under `.claude/worktrees/x` is not denied by these rules. Test `F1-skill-protect-no-overblock`.
8. Each `authorable-content-protected` residual's condition is checked, not asserted: the helper maps that condition to its required protected entries, and the test fails if a judged tool carries it while any such entry is missing from `PATHS.named`. Test `K-residual-condition-has-instrument`.
9. ADR-0003 tests pass unchanged: `adr0003-write-path-claim-matches-pending-list`, `adr0003-no-retyped-tool-list`.
10. The `inner-calls-gated` condition is recorded as OPEN, not satisfied: the K md carries a "K release gate" line naming the live subagent probe for Task, SendMessage, Workflow, and a test asserts the line exists while those tools carry the condition. Test `K-inner-calls-condition-recorded`. (No CI test depends on the probe result; see question 2.)
