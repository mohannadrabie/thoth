## 1. Restatement

The protected-path generator (`src/qa/protected-path-list.ts`) must also protect the repo scripts that enabled plugins' hooks execute. They are derived from the hook commands, not typed by hand, and flow into the one existing list that feeds `src/policy/config/shipped-defaults.json` and the Edit-deny proposal.

## 2. Findings from the read

- **How the list is built today.** `protectedPaths(root)` has `generated` (the hook file plus scripts named in the project settings and the gitignored local settings hooks, found by the CLAUDE_PROJECT_DIR regex in `wiredHookScan`, then expanded through the import graph and the read-by-path data files) and `named` (hand-typed). Rules and the proposal are rendered from the one `all` list by `renderShippedDefaults` and `buildSettingsProposal`. `--write` regenerates both; the default run checks drift. CI does not run this script directly; drift is checked by the tests and by k-readiness.
- **The three scripts are the gap.** The maat hook has no CLAUDE_PROJECT_DIR. It is an inline `node -e "..."` with the relative literals 'docs/session-brief.mjs' and 'docs/adr-cache.mjs'. The settings scan would throw on that shape, so it needs a separate path.
- **decisions-archive.mjs is not named in the hook command.** It is spawned by `docs/session-brief.mjs` (`execFileSync(process.execPath, ["docs/decisions-archive.mjs"])`, and likewise adr-cache). The import-graph walk does not follow spawns, so deriving from hook-command literals alone would miss it. A spawn-follow step is required.
- **Hooks in this repo's own `.claude/settings.json`: already covered.** SessionStart `hooks/sessionstart-tool-enum.mjs` and UserPromptSubmit `hooks/userpromptsubmit-halt-relay.mjs` are in `protectedPaths(root).all` today (I ran it; the list has 122 entries, not the 111 the issue recorded). They are covered through `wiredHookScripts` and the import graph. No change is needed; a test will assert they stay covered.
- **Where plugin data lives.** `~/.claude/settings.json` has `enabledPlugins` (maat@maat true). `~/.claude/plugins/installed_plugins.json` gives installPath, version and gitCommitSha. The maat 2.0.0 install has both hooks/hooks.json and hooks.json (identical today), with a single SessionStart inline `node -e` command. shopify-ai-toolkit 1.8.4 runs `bash "${CLAUDE_PLUGIN_ROOT}/hooks/scripts/track-telemetry.sh"`, which resolves inside the plugin install directory.
- **F1-settings-named-scripts-judged.** `src/qa/k-readiness.ts` lists it as an expected row. Its instrument (src/qa/f1-settings-named-scripts-judged.ts, new) and its npm script do not exist yet; `src/qa/k-readiness.test.ts` deletes the script and expects the row MISSING. The wiring plan row at line 103 of `docs/plans/s308-K-wiring-plan-2026-10-05.md` is the spec.

## 3. Design

### Where the enabled-plugin set and hook commands come from

- A committed snapshot, docs/qa/plugin-hook-snapshot.json (new, generator-produced). Per enabled plugin: id, version, gitCommitSha, each hooks file path relative to the plugin, the file's sha256, and the extracted command list.
- Local `--write` reads: user, project and local `enabledPlugins`; installed_plugins.json for the install path; the plugin's hooks files (hooks/hooks.json and hooks.json, both read and unioned, plus plugin.json's hooks field if it names another file). It refreshes the snapshot.
- The default check run (CI or local) reads only the snapshot, because there is no ~/.claude in CI. It re-derives the script list from the snapshot commands and compares to the committed shipped-defaults.json and the proposal (the existing drift check, now covering the new paths). It also verifies the snapshot's internal consistency (stored hash matches stored commands).
- Drift of the snapshot against the real plugin:
  - Locally, when ~/.claude/plugins exists, the check re-reads the live hooks files and compares hashes and the enabled set to the snapshot. A mismatch exits 1 ("plugin hooks changed since snapshot; run --write"). The F1 row runs this local check; K is a local, human-run activation, so that is where live equality is certified.
  - In CI it cannot be detected (no live plugin). CI proves only that the committed list is consistent with the committed snapshot. Disclosed limit.
  - If ~/.claude/plugins is absent locally, the check reports "unverified", not "pass".
  - A plugin enabled but absent from the snapshot is caught locally by the same check.

### Deriving scripts from a command

- New `pluginHookScripts(snapshot)` inside `src/qa/protected-path-list.ts` (already protected; one list, no second copy).
- Extraction: collect CLAUDE_PROJECT_DIR captures as the settings scan does, plus quoted and bare tokens with a script extension (mjs, js, cjs, ts, mts, sh, ps1, py), canonicalized.
- Classification:
  - Resolves inside the repo (relative, and existing on disk at generation time): protected.
  - Starts with CLAUDE_PLUGIN_ROOT, is absolute, starts with ~, or escapes the repo with "..": reported, not protected. Plugin-root paths are already under the protected ~/.claude/plugins/.
  - A command with no extractable script is listed as unenumerable. It is not thrown (Manager ruling 2); the F1 row fails until the human judges it.
- Spawn-follow, applied only to roots derived from plugins: a literal TS AST scan of execFile, execFileSync, spawn, spawnSync and fork calls whose command is process.execPath or "node" and whose args name a repo script literal, iterated to a fixpoint. It throws if such a call has a non-literal script argument (fail closed, as #418). This follows `docs/session-brief.mjs` to `docs/adr-cache.mjs` and `docs/decisions-archive.mjs` without hand-typing. It is not applied to the gate closure, to avoid changing the existing list.
- The derived scripts are also added as roots to `importGraphFiles` so relative imports are followed (today all three import only node: modules).
- Disclosed limit: a plugin hook reaching a repo script only by a runtime-built path is not enumerable.
- Consequence to disclose: once protected, a plugin upgrade that rewrites docs/*.mjs through /maat:init needs the human, not the session. Intended.

### F1 precondition

- Create src/qa/f1-settings-named-scripts-judged.ts (new) and the npm script qa:f1-settings-named-scripts-judged, so the k-readiness row stops being MISSING.
- It checks: every script named by a settings or plugin hook command is in the protected list or reported as outside the repo; the snapshot matches live (local only); no unenumerable command is unjudged.
- This extends the F1 precondition to plugin hooks, as the issue asks. The other settings fields (statusLine, apiKeyHelper, awsAuthRefresh, otelHeadersHelper) stay with the human's read-only listing; this story does not enumerate them.
- `src/qa/k-readiness.test.ts` counts missing rows; wiring F1 changes that expectation, so that test is edited.

## 4. Acceptance criteria (each mapped to a named check)

1. A plugin hook command naming repo scripts yields those paths; one resolving outside the repo is reported, not protected. Check: `plugin-hooks: derive in-repo scripts, report outside-repo` in `src/qa/protected-path-list.test.ts`.
2. The real maat snapshot yields docs/session-brief.mjs, docs/adr-cache.mjs and docs/decisions-archive.mjs, the last via spawn-follow. Check: `plugin-hooks: maat snapshot yields session-brief and its two spawned children`.
3. Completeness (hard rule): adding a hook command to the snapshot adds its script to `protectedPaths(root).all`, removing it removes the script; the deny rules and Edit-deny proposal follow. Check: `plugin-hooks: adding/removing a hook command changes the list` (synthetic snapshot, injectable reader).
4. One list: plugin-derived paths are in `generated`; shipped-defaults.json and the proposal are regenerated from it; the default run exits 0 only if they match. Checks: `qa:protected-path-list` drift check, plus `plugin-hooks: generated rules and proposal include derived paths`.
5. A spawn with a non-literal script argument throws; a literal spawn is followed to a fixpoint. Checks: `spawn-follow: computed script throws`, `spawn-follow: transitive fixpoint`.
6. Snapshot drift: stored hash mismatch exits 1; live hooks hash differs (injected live reader) exits 1 naming the plugin; an enabled plugin missing from the snapshot exits 1; no live plugin dir reports "unverified", not pass. Checks: `snapshot: internal hash mismatch fails`, `snapshot: live drift fails`, `snapshot: missing enabled plugin fails`, `snapshot: absent live dir is unverified`.
7. This repo's own sessionstart and userpromptsubmit hook scripts remain protected. Check: `protected-path-list: repo settings hooks stay covered`.
8. The F1 instrument exists and runs; it fails on an unprotected in-repo plugin script and on an unjudged unenumerable command. Checks: `f1: fails on unprotected plugin script`, `f1: fails on unjudged unenumerable command`, and the k-readiness row PASS with its test updated.
9. Editing any of the three scripts is denied by the generated rules and the Edit-deny entries. Check: existing `unmatchedPaths(rules, all)` is empty, asserted over the new paths.
10. Existing gates stay green: qa:k3, qa:k5, qa:k-merge, and the reference-resolver in CI diff mode (`reference-resolver.ts origin/master HEAD`). Checks: those named runs, with real counts.
